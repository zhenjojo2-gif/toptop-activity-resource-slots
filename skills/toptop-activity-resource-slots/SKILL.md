# TOPTOP 活动资源位制作

根据本次设计稿、需求和翻译表制作可编辑 Figma 成品。通用规则长期复用；每个新活动重新建立国家、语言、时间、奖励、key 和素材映射，同一活动续做复用有效记录，不从旧活动继承内容。

## 入口与模式

先识别「制作」「只检查资料」或「创建/修改 Skill」。后两者不提交生图任务、不创建正式资源位。

| 模式 | 适用输入 | 执行流程 |
|---|---|---|
| 模板适配 | 已排好构图的资源位模板，文案与奖励可以是占位 | [template-mode.md](references/template-mode.md) |
| 主视觉延展＋自主排版 | 活动头图主视觉，没有已排好的资源位范例 | [kivi-layout-mode.md](references/kivi-layout-mode.md) |

用户选择优先。未说明时先检查设计稿：有现成资源位模板则走模板适配；只有主视觉则说明采用主视觉延展模式。两种输入并存且意图不明时只问模式。测试无范例排版能力时，不拿现成活动资源位成品充当排版参考。

制作输入为本次 Figma 设计稿、需求文档、翻译表；默认在本次设计文件的独立输出页面制作。模式二通过 Chrome「Kivi 画布快生成」侧边栏执行图生图，同一活动共用一张生成画布，续做时复用已记录的 URL/ID。

## 增量执行与调用节制

- 已读且未变化的技能文件不重读。只加载当前模式；生成弹窗才读弹窗流程，自主排版/复盘才读版式复盘。模式二转国家适配时复用基线，跳过首例建立。
- 工作目录保存一份状态：来源 URL 与 revision/核对时间、规范与内容映射、基线/输出节点 ID、图片 hash/路径、Kivi 画布/任务、验收及缺项。共享数据存一次，各输出引用；状态不写入技能。
- 首次读相关来源；续做只核对变化、缺失及本次修改依赖的字段。revision 相同复用缓存，无 revision 则定点核对，不重扫整份资料或全部页面。用户新稿更新对应基线。
- 一次索引相关节点和 key × locale，后续按 ID/路径操作。独立读取批量并行，依赖操作顺序执行，遵守工具批量及错误恢复限制。返回 ID、尺寸、变更字段和异常，不输出完整树、表格或历史。
- 同一 hash 复用导出、上传与合格背景，源图/目标变化才重做；Figma 按国家/语言/资源位身份定点更新。来源失败定点重试一次，仍失败只登记依赖该来源的缺项，保留有效记录。按 [acceptance.md](references/acceptance.md) 增量验收。

## 先读取并建立映射

1. 读取 [fixed-spec.md](references/fixed-spec.md)，按缓存策略核对本次涉及类别的规范标注，记录日期、节点与版本线索。区分说明分区、成品画布、内容容器与安全区。
2. 读取本次需求的资源位章节、国家/语言清单、实际时间表、奖励附件和布局要求。结合截图识别合并单元格及图片表格。示例日期、模板文案、占位奖励不能成为真实内容来源。
   - 时间直接采用对应国家“活动时间（本地）”原文，完整口径见 [content-mapping.md](references/content-mapping.md)；不自行简写或换算。
3. 按 [content-mapping.md](references/content-mapping.md) 查找精确 key 与语言列，建立每个输出的文字及素材映射。国家与语言分别记录，不根据国家猜单一语言，也不因翻译表有某语言就增加对应国家。
4. 只读检查 Figma 图层和截图，定位文字、标题、奖励图片、奖励框、日期、按钮和固定装饰；记录来源节点与有效基线。模式二读取主视觉与可用分层素材。
5. 简短整理已确认范围与关键缺项。能从资料查明的自行查；只问无法确定且下一步确实依赖的问题。缺项只暂停受影响版本或字段，其他资料完整部分继续。

优先使用可用连接器；Figma 使用 metadata/只读 use_figma 配合截图。连接器失败可通过已登录浏览器读取可见资料。说明实际读取范围，不能把「已打开页面」「看见表名」当作完整读取；不使用 Cookie、隐藏应用状态或猜测接口读取数据。

## 工具和授权

- 使用 Figma 写入或 Plugin API 检查前，加载当前 `figma:figma-use` 并查阅实际支持的 API；完整布局按其要求加载设计流程技能。无需把资源位制作扩展成设计系统重建。
- 模式二先读 [kivi-quick-panel.md](references/kivi-quick-panel.md)，使用用户指定的 Chrome 扩展「Kivi 画布快生成」。通过当前 CUA 文档支持的浏览器/原生 Chrome 界面操作其侧边栏；它与 Codex 的 `kivi-browser:kivi-generate` 技能不是同一个入口，不自动改走网站节点生图、聊天生图或其他平台。
- 生图默认使用 **GPT image2.5**，**每次生成4张独立候选图**，包括首页弹窗合成及定向修正；用户当次另行指定时覆盖。通过插件的模型和数量控件设置，不用提示词拼出四宫格。执行时核对实际可用选项，不能把GPT Image 2当作2.5或静默换模型。
- 用户选择模式二并要求制作，即授权为该活动新建 Kivi 无限画布，以及必要的图生图、扩图、去除底图文字/奖励和背景修补，无需逐张确认。只写 Skill 或讨论方案不新建生产画布、不提交生图。
- Kivi 不可用、登录失效或无法接入参考图时说明具体阻塞，不自动换平台，不用纯文生图冒充图生图。
- 保留原设计和原模板，仅改独立输出页的副本；不修改共享母组件而间接改变原设计。出错后先核对实际已写入节点，再定点恢复，避免重复复制。

## 共同调整边界

尺寸、格式和特殊字段按固定规范；制作范围、真实时间与奖励按本次需求；翻译正文按精确 key 与语言列；模板构图按本次设计。来源冲突列明证据，不静默覆盖。用户本轮明确的新指令优先，并记录覆盖项。

| 对象 | 允许调整 | 保持固定或先确认 |
|---|---|---|
| 开屏说明 | 在既定宽度内折行，必要时增加文字背景高度 | 说明字号、外画布尺寸不变；不能挤动其他固定元素或侵占安全区 |
| Chatroom/Activity Banner、首页弹窗、礼物 Banner 普通文案 | 溢出时在适用下限内调整字号；按下述信息组规则对齐和平移 | 文字背景高度、区域宽度不变；不单独压缩字距或行距掩盖溢出 |
| 日期、按钮、数字等特殊字段 | 按专门规则处理；日期可按下述信息组规则重新居中 | 普通文案缩字权限不覆盖特殊字段规定 |
| 标题素材 | 换对应国家/语言资产，在固定槽内保比例适配；按下述信息组规则对齐和平移 | 槽的尺寸不变，不拉伸、不自行重译或重画 |
| 奖励图片 | 按需求调整数量、顺序、布局；放不下可等比缩小 | 不拉伸、不裁主体、不用错误素材补齐 |
| 奖励框/底座/容器 | 双奖励按下述规则随对应图片平移；其他增减、缩放、重排按需求明确权限 | 图片权限不扩展到框的数量和尺寸；不能整体缩放图片与框后声称只缩了图片 |
| 其他固定元素 | 已明确授权的变化 | 尺寸、位置、层级和构图不变；规范要求的地域布局例外单独记录 |

上述允许缩字的普通文案默认最低 **16px**，来源为用户确认的通用规则。开屏说明仍锁定基线字号；日期、按钮、数字及 Live banner 等专门规定优先，不套用此下限。适用范围以外的字号下限未知且需要缩小时，才登记缺项。

模式一基线来自有效模板；模式二可自主建立基础版式。自主排版或复盘用户改稿时，读取 [layout-review-rules.md](references/layout-review-rules.md)，判断标题占比、信息分区、文字对比和场景融合。行距、元素间距和奖励间距按本次活动确定，同一活动的同类资源位、相同字号或相同奖励数量采用统一规则；不同规格不强行共用同一像素值。不将本次活动的间距、字号与行距配对、中心坐标或位移量写成跨活动常量。检查通过后记录本次基线，再派生国家版本。用户提供已按要求修订的稿件时，以实际图层属性和截图更新本活动基线；不因旧图层名称或旧待确认记录而退回旧值。

### 信息组对齐与双奖励布局

- 先识别模板的信息分区与对齐方式。采用居中叠放的同一信息区内，标题、文案、时间共用水平中心线，基准是该信息区，不一定是整张画布。采用分栏布局时，各栏独立对齐；例如左侧标题、右侧说明与奖励，右栏可共用左边线，不能把两栏强行拉到同一中心线。日期替换后按所属信息区重新定位，不沿用占位日期的左坐标；不因此增补需求未要求的字段或改变日期的上下顺序。
- 右侧奖励遮挡文字时，可将受影响的完整信息组适当左移，说明背景随文案平移且宽高不变。保持该信息组原有的居中或左对齐关系，检查安全区、边界和新遮挡；不删字、不拉伸图片，不挪动无关固定元素。此对齐与平移权限不改变开屏字号或特殊字段规格。
- 奖励数量明确为两个且奖励框数量已按需求落实后，采用紧凑的双奖励布局，并在原奖励区域内整体居中，不保留三奖励布局的空位。图片与对应奖励框一起平移，尺寸不变；已紧凑居中的版本不再无故缩小间距。框的增减、缩放仍须有需求或用户确认依据。
- 某个国家暴露出共性版式问题时，检查并修正全部适用的同类版本，按各语言实际内容计算位置；双奖励规则只应用于双奖励版本。结构与截图共同验收，具体执行见 [template-mode.md](references/template-mode.md) 与 [acceptance.md](references/acceptance.md)。

仅需生成首页弹窗背景时读取 [popup-background.md](references/popup-background.md)：两张参考加一句提示词；增高只延长中段，不拉伸整图。已有合格背景直接用于国家派生。

## 组织、验收与交付

- 画布命名 `国家简称/资源位名称`，例如 `JP/开屏`。同国多语言/变体放入不同父 Section，记录 locale 和变体身份，保持画布命名格式并避免覆盖同名版本。
- 保留可编辑文字与独立背景、标题、奖励和按钮层。现成标题图片可作为独立素材；说明、日期、按钮文案不能烘焙到背景。
- 仅制作需求清单里的输出。Chatroom 和 Activity 若明确共用一张图，记录两个投放项与一个物理画布的关系；未明确时不擅自合并或重复计算。
- 本次内容映射、节点 ID、基线、Kivi 任务和缺项可存本地工作目录以便恢复，不能写入 Skill 成为下次默认值。
- 制作后执行 [acceptance.md](references/acceptance.md)。结构和清晰截图检查都通过才标记合格，未检查与缺项单列。
- 最终只交付 Figma 输出页/画布链接、完成范围和缺项。PNG/JPG 规范用于画布/导出设置检查，不额外交付切图、压缩包或视频，除非用户要求。Kivi 链接用于追溯，不替代 Figma 成品。

## 使用方式

`使用 $toptop-activity-resource-slots，按模板适配制作。设计稿：…；需求：…；翻译表：…；输出到独立页面。`

`使用 $toptop-activity-resource-slots，按主视觉延展＋自主排版制作。主视觉 Figma：…；需求：…；翻译表：…。为本活动新建一张 Kivi 无限画布。`
