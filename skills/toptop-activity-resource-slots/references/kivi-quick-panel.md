# Kivi 画布快生成插件操作

指定入口为 Chrome 扩展侧边栏「Kivi 画布快生成」（面板标题「画布快生成 / KIVI CANVAS」）。通过它的「图生图」生成并保存到 Kivi 画布，合格结果随后进入 Figma。不要因名称相近而改用 Codex 的 `kivi-browser:kivi-generate` 网站节点流程。

## 连接与目标画布

1. 每个活动开始生素材前，通过当前 CUA 可见界面新建一张 Kivi 无限画布，以实际活动名称标识，并记录 URL/ID。新建入口以当时界面为准，不猜按钮或 API；无法新建时说明阻塞，不退回其他活动的画布。用户选择模式二并要求制作已包含新建授权。只编写 Skill 或检查资料时不实际新建。
   同一活动的所有规格、国家与修正任务放在这张画布；中断续做先检查本活动记录，恢复已新建的画布，不能每次重试或每个国家都新建。用户提供的旧画布可作为明确指定的参考来源，不默认作为本活动生成目标。
2. 将该画布置为 Chrome 当前标签页，打开工具栏「Kivi 画布快生成」。侧边栏属于 Chrome 扩展界面；网页 DOM 无法访问时，使用原生 Chrome 的可访问性树和截图，不猜扩展内部 API。
3. 检查「已连接」与「当前画布」两处。已连接不代表已识别画布；若仍提示「请在当前标签页打开 Kivi 画布」，点击面板「刷新」，再次核对画布名称/ID。刷新后仍不匹配则暂停提交并说明具体状态。
4. 只读取本次控件和本次任务，避免遍历无关生成历史。不清理历史、不改写旧任务、不切换用户账号。

## 参考图与参数

1. 选择「图生图」。从已读 Figma 主视觉提取参考，优先无文字底图或分层资产。
2. 两种可见输入方式：从「选择画布参考图」选中正确图片后点「添加」；或通过「上传本地参考图」上传已核对的本地图片。选择器/文件对话框只用 CUA 文档支持的操作，无法接入时明确阻塞，不用纯文生图替代。
3. 逐张核对参考缩略图、文件/节点身份、参考数量及顺序。清除本任务误带的旧参考，不凭同名节点判断图片正确。多参考时在 prompt 中说明每张用途，避免将资源位成品误当原始 KV。
4. 默认将模型设为 **GPT image2.5**、数量设为 **4**；首页弹窗合成和定向修正同样适用，用户当次明确指定的值优先。核对模型实际标签与身份，不把GPT Image 2视为2.5；若没有所需模型或数量选项，报告具体阻塞，不静默降级或重复提交凑数。比例、清晰度、背景按目标及实际可用控件设置，不从其他模型/历史结果推断能力。
5. 核对模型对应的参考数量、格式、单图大小限制。不支持精确尺寸时按目标裁切需求选比例，事后检查真实像素。未出现的自定义尺寸、蒙版、参考权重等能力均不能假定存在。

## 提交与恢复

- 仅在用户要求实际制作时，核对目标画布、图生图模式、正确参考、完整 prompt 和参数，点击一次「生成并保存到画布」。编写/修改 Skill 或只读核验不提交。
- 记录并跟踪该任务的 ID 和状态。提交超时或页面通信中断，先查原任务及目标画布，不盲目再点生成。
- 区分生成中、生成失败、图片已生成但保存待重试、已保存到画布。若只保存失败，核对是否已存在结果节点，再用该任务「重试保存」恢复；不为保存问题重复生图。
- 使用本次任务的「生成结果」「打开结果画布」核对实际图片、数量和目标位置；默认应有4张独立候选，逐张看图比较主视觉一致性与构图，选合格且最适合排版的一张使用。四宫格不算4张独立结果；结果不足4张则如实记录状态，先核对原任务，不直接重提整批。不能仅因显示「已保存」就认定图片合格。
- 定向修正继续通过此插件的「图生图」入口，可将本次合格部分所在结果作为参考；只有核对素材身份后才使用「用作参考图」。保留原始 KV 的身份约束，不引入无关历史图片。
- 插件缺失、登录失效、画布识别失败、参考接入失败或额度错误，记录受影响规格与具体提示，继续可独立处理部分。未经用户新指示不换生成入口或平台。

## 已核对界面与未验证能力

2026-09-21 对 v1.0.2 进行只读核验：刷新后能识别当前画布；可切换图生图；提供画布参考选择、本地参考上传，以及模型、比例、清晰度、数量、背景控件。所见 GPT Image 2 界面提示最多 10 张参考图，格式 PNG/JPEG/WebP、每张不超过 10 MB。这是该版本与当时模型的界面标注，执行时必须重新核对，不作为所有模型的永久规则。

用户后来将默认模型指定为GPT image2.5、每次4张；这是制作偏好，尚未完成该模型可用性与参数的实际核验。上面的GPT Image 2观察记录不能作为2.5已验证的证据。

本轮未新建生产画布、上传参考或提交任务，未穷举模型和参数选项，未验证实际生成、保存恢复及 Figma 导入。不要将控件存在描述为生产链路已经测试通过。
