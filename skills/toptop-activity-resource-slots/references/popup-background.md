# 首页弹窗背景合成

用于需要生成首页弹窗背景的主视觉延展流程。输入是本次设计稿中的弹窗背景框和活动主视觉，默认生成4张候选，验收后选用1张合成图片作为 Figma 弹窗的背景图。模板适配仅替换内容时不自动重做背景。

## 1. 定位背景框并准备本地参考

1. 在本次 Figma 设计稿中结合图层、属性和截图找到弹窗背景框，记录来源节点。它应包含需要保留的边框、底色及边缘装饰，不带标题、说明、日期、按钮文案或奖励。按本次真实素材识别；示意图中的紫色、花朵、星星不作为以后活动的固定样式。找不到或有多个无法判断的候选时只暂停弹窗项，不自行另画一个框。
2. 将背景框复制到独立输出页的素材准备区，保留原设计不动。将整个背景框副本拉伸至 **750×825**，实际框体内容应随之适配；不能只改外层空画布的宽高而框体不变。此处明确允许按目标宽高拉伸，不受其他素材等比缩放规则限制；权限不扩展到人物/IP、奖励图片、奖励框或已确定的国家版式。
3. 将该副本以 **2× PNG 导出到本地**，实际文件应为 **1500×1650**，宽高比 **10:11**。导出范围包括完整边框与装饰；保留源素材的透明区域，不把 Figma 编辑器灰底或截图背景导入图片。
4. 查看本地导出图并核对真实像素，排除边缘装饰被裁、漏层、错误底色、文字/奖励残留。记录本地路径与源节点，后续上传使用这张已核对图片，不能用截图替代2×导出。

750×825是本流程的背景素材准备尺寸，1500×1650是2×导出的实际像素；二者均不自动改写成品外画布规范。使用时读取 [fixed-spec.md](fixed-spec.md)，区分背景图片尺寸、内部内容容器和成品外画布，不自行把整张弹窗改成750×825。

## 2. 在本活动的新画布中合成

通过 [kivi-quick-panel.md](kivi-quick-panel.md) 在为本活动新建的 Kivi 无限画布工作。图生图参考按顺序接入：

- 图1：本地导出的1500×1650弹窗背景框。
- 图2：从同一活动设计稿提取并已核对的主视觉，优先无文字/奖励版本。

核对缩略图、参考数量及顺序，默认设置模型为 **GPT image2.5**、生成数量为 **4**。检查实际可用比例与模型限制；有10:11则选用，没有则选能保留完整边框和主视觉的比例，要求框外留出可裁余量，结果仅在不裁边框/关键主体的条件下适配。不能把2K设置当作1500×1650的精确输出承诺。

提示词按本次真实主体和信息区填入：

```text
图1是已按目标尺寸准备好的首页弹窗背景框，图2是本活动主视觉。
每张候选均为完整的合成背景图：将图2的主视觉自然安排到图1的框内，不拼四宫格或多图版面。
保持图1现有外轮廓、边框厚度、颜色、材质与边缘装饰，保留框与装饰对框内场景的遮挡关系，不重画或更换框样式。
保持图2的{人物/IP身份、主题元素、配色、材质、光照和渲染风格}。
在内框中调整主体位置、场景范围和背景衔接，主体完整，不拉伸人物，不直接把整张主视觉挤进框内。
为后续独立排版的{本次标题、说明、奖励、日期和按钮所需区域}留出可用空间。
不生成标题、说明、日期、按钮文案、奖励图片、数字或伪文字；去除原主视觉中这些内容并自然修补。
完整保留背景框及装饰边缘，合成背景最终按10:11、750×825使用。
```

核对后通过插件提交一次，默认得到4张独立候选，逐张验收后选用1张作为背景；不是每个国家分别生4张。只有需要修正具体缺陷时再按已有授权定向修正，修正也遵循默认模型和每次4张，除非用户另有指定。

## 3. 验收并导入 Figma

- 对照图1检查框的形状、材质、装饰和完整边缘，对照图2检查人物/IP、主题、光照和主体完整性；检查框内衔接、遮挡关系、排版空间及伪文字/旧奖励残留。
- 合格结果作为单独背景图片层导入，按750×825的背景素材尺寸使用，放入规范要求的成品画布；按已确认构图安排锚点，不能裁掉外框装饰或为贴合外画布再次非等比拉伸。
- 本步骤允许边框与框内主视觉合成在同一张背景图中；原框与主视觉来源副本仍保留。标题、说明、日期、按钮文案和真实奖励继续独立排版，文字保持可编辑，不能将整个弹窗扁平化。
- 基础版式确定后锁定合成背景，各国家按共同适配规则派生；仅文案变化复用同一背景。当地需求确有视觉差异时才另行处理。
- 缺背景框、缺主视觉、无法2×导出、参考接入失败或完整边框无法适配时，列明弹窗项阻塞并继续其他完整资源位；不能以无框背景或拉伸人物替代。
