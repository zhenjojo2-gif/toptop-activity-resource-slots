# 主视觉延展＋自主排版

正常制作包含Kivi图生图，不止编写prompt。只要求创建/修改Skill或检查资料时，不执行生图与Figma写入。

## 1. 提取主视觉并规划规格

只读识别活动头图，结合图层和截图分析人物/IP身份、脸与服装特征、姿态、配色、材质、光照、场景和装饰。记录参考节点、来源及实际像素尺寸，先看图再使用。

优先读取无文字底图与分层资产；无需修改原设计来临时隐藏图层。没有干净素材且用户已选择本模式制作时，允许通过Kivi去除头图中的文字/奖励并修补背景，检查是否残留。

根据实际输出清单按宽高比、主体锚点和信息区需求分组。只有比例与布局需求一致才能复用背景，不同比例分别适配。先按真实长文案和奖励需求规划标题、说明、奖励、日期、按钮的可用空间，再决定画面构图，不能只拉伸或整体缩小原图。

包含首页弹窗时，先按 [popup-background.md](popup-background.md) 定位并复制本次设计稿的弹窗背景框，拉伸为750×825并2×导出到本地，再以背景框＋主视觉双参考合成。这个准备步骤中的背景框拉伸是明确例外；其他主视觉延展仍遵守不拉伸图片的规则。

## 2. 检查当前Kivi能力及参考输入

- 按 [kivi-quick-panel.md](kivi-quick-panel.md) 使用 Chrome「Kivi 画布快生成」侧边栏，只用当次CUA文档公开的接口。网站普通图片节点和聊天输入框不能替代用户指定的插件入口。
- 为本活动新建一张无限画布，续做时恢复该活动已新建的画布；检查登录、插件连接及当前画布，选择插件「图生图」，读取实际模型、参考上传/选取方式、尺寸/比例、清晰度、数量和任务状态。不猜测自定义像素尺寸、seed、参考权重、蒙版或扩图API。
- 使用插件「选择画布参考图」并「添加」，或「上传本地参考图」接入已提取主视觉；提交前看到本任务参考缩略图、数量及素材身份一致的可见证据。只在prompt中写「参考原图」不算图生图。
- 没有独立扩图入口时，可用实际支持的图生图要求扩展场景并核验结果；根本不能接入参考图则暂停，不能降级纯文生图。
- 按目标规格选择实际可用比例与质量，用户指定参数优先；插件当前值或历史任务参数不能覆盖资源位比例。不支持精确尺寸/比例时选可保留主体的合适比例，后续保比例裁切。记录选项和结果真实宽高，不能把2K等同于固定像素值。
- 插件不可用、登录失效或缺参考素材时说明具体阻塞，不自动换生图平台。Figma导出、Kivi参考上传、结果导入都是模式二制作范围内的必要操作；只读/技能编写任务不执行这些生产动作。

## 3. 编写并执行提示词

每组共享视觉约束，只调整目标比例/构图。下面花括号由本次已读资料填入，不是平台API参数：

```text
基于实际上传的主视觉进行图生图延展，用于{资源位}。
保持{人物/IP识别特征、主题元素、配色、材质、光照和渲染风格}。
生成比例为{平台支持选项}，最终用于{规范宽×高}。
按{延展方向、场景范围、主体锚点与大小关系}重新安排构图，保留完整关键主体。
为随后独立排版的{标题、说明、奖励、日期及按钮所需区域}留出清楚净空。
只生成背景与主视觉，不生成标题、说明、日期、按钮文案、奖励图片、数字或伪文字。
若原图带有以上内容，干净去除并自然补齐背景，不能留下残影或相似字形。
不更换人物/IP身份、活动主题或整体风格，不拉伸原图，不以整体缩小代替场景延展。
```

横向Banner避免主体占满信息区、人物被裁或信息过密；小入口保留清楚的主题识别。只预留本次需求实际要求的字段，不强行塞入所有内容。

所有生图默认使用GPT image2.5、每次4张独立候选，定向修正同样适用。首页弹窗使用专门的双参考合成提示词，生成4张后验收选用1张；须保留已准备背景框的轮廓、边缘装饰及遮挡关系，把主视觉安排在框内，不套用普通背景延展而重新生成一个框。

在插件中核对参考、prompt、参数、数量及目标画布后，点击一次「生成并保存到画布」。不覆写历史节点；记录本次任务ID、prompt、参考、参数、状态、实际结果地址与尺寸，另记已保存的画布/节点。超时先查原任务，不重复点击生成；若「图片已生成 · 保存待重试」，核对是否已落到目标画布，必要时使用该任务的「重试保存」，不重新生图。配额/登录/平台错误报告具体原因，继续独立工作，不自动换入口或平台。

## 4. 看图与定向修正

每批候选都逐张看图比较，核对主体完整、人物脸/服装/IP一致、身体装饰无明显畸变、场景衔接、光照配色材质、信息区净空，以及文字/旧日期/奖励残留；选择合格且适合本次排版的结果，并记录所选图片/节点。

有明显问题时保留正确部分，用Kivi只修具体问题，例如「保持人物和光照，补齐左侧背景并清除残字」。必要修正已获模式二制作授权，不逐张询问。相同问题连续两次定向修正仍无改善，或继续需更换主题/IP时，暂停该组并说明已试方案，避免无限生成。

比例不精确时先等比缩放，再在固定画布里裁切；逐边核验裁切量、主体和净空。不能非等比resize或牺牲关键人物。无法安全裁切则回Kivi调整构图。实际结果不符合精度/清晰度时按平台已验证能力处理，不假称已精确生成或修复成功。

## 5. Figma排版与国家派生

将合格背景导入独立输出页的固定尺寸画布，保持图像比例。添加独立国家/语言标题资产、可编辑说明/日期/按钮文字、真实奖励及所需元素。Kivi不负责真实文案和奖励替身。

自主安排信息层级与区域，应用主入口的信息组居中与双奖励布局规则，建立本活动统一的行距和间距规则；检查真实长文案、最多奖励及实际需要的双奖励版本。缺关键规格时按缺项规则处理。资料与视觉检查通过即可确定基础版式，不额外设逐张批准流程。

记录基础节点与截图，锁定背景、主体、标题槽尺寸、装饰、按钮和各内容区域基线；信息组对齐、避让与双奖励平移仍按主入口的明确规则执行。所有国家从同一基础版式派生，按 [template-mode.md](template-mode.md) 适配。仅文案变化复用背景；其他视觉变化只有明确需求或已证明不能满足限制时才另行处理。

按 [acceptance.md](acceptance.md) 联合检查生成视觉、Figma图层与各国语言截图。Kivi任务完成不等于资源位合格。
